# KIR v2 work plan

The design is in the "KIR v2 Design Notes" artifact
(https://claude.ai/artifact/FARrzSKom6hZUo36Y9EpKW); `docs/spec/` turns it
into the specification. Phases run in strict order. Each one is implemented in
full, reviewed by reading, then checked, before the next starts.

The Togeari machine receives KIR text plus engines and never cares how the KIR
was produced, so the node editor is an example client, not part of the core.

## Phases

- [x] **0. Setup**: v1 reference results recorded (`tests/corpus/v1`), v1 code
  cleared (git keeps its history), skeleton and tooling.
- [x] **1. Spec** (`docs/spec/`): language, semantics, graph view, optimization
  passes, checks, signatures and `@use`. Reviewed by the user before code.
- [x] **2. Python reference** (`src/kohakunode/`): syntax, signatures, checker,
  text ↔ graph view, optimization passes, interpreter, CLI, ComfyUI import /
  export.
- [ ] **3. Rust core** (`rust/`): parser, checker, graph, passes, writer;
  PyO3 and WASM bindings; byte-identical to Python.
- [x] **4. Editing**: tree-sitter grammar, VS Code highlighting and snippets,
  and a language client that launches `kir-lsp`.
- [x] **5. Examples and docs**: v1 basics ported, v2 feature tour, GBC with
  stub nodes; README, architecture, guides.
- [x] **6. Node editor** (example app): Vue 3, Vue Flow, elkjs, UnoCSS; the
  new shapes; Graph / Blocks / Text views; palette from signature files; undo /
  redo; one browser smoke script (`npm run test:e2e`).
- [x] **7. Language server**: basic, `kir-lsp` (Python, on the reference, so
  diagnostics equal `kir check`): diagnostics, hover with node signatures,
  completion of nodes / labels / directives, go-to-definition, formatting.

## Layout

```
docs/        spec/ · plan/ · guides/
src/kohakunode/
    syntax/   kir.lark · parser · ast · writer
    sig/      node registry · signature JSON · @use loader
    check/    the checker rules
    graph/    graph view schema · text → graph · graph → text
    lower/    optimization passes and program hashes
    run/      sequential reference interpreter and its call hook
    cli/      kir check | fmt | graph | lower | run | sig
    comfyui/  ComfyUI workflow import / export
rust/        the Rust core and its PyO3 / WASM bindings
editors/     tree-sitter-kir · vscode · language server
apps/        kir-editor (example node editor)
examples/
tests/       corpus/ (inputs, golden outputs, v1 reference) · checks
```

## Not carried over from v1

- v1's scheduling and CSE passes: scheduling belongs to the machine, and CSE would merge
  two identical model calls that are meant to be two samples.
- The custom layout code: the editor lays out with elkjs.
- `app/` and `kohakunode_viewer/`, which only held copies of the Python package.

## Checks

The only automated tests; each can fail on a broken build.

- Golden canonical text, optimized text and graph view for every corpus file,
  compared by hash.
- v1 parity: for every `ok` file in `tests/corpus/v1`, v2's interpreter on its
  fully optimized program reproduces the recorded stdout and final
  source-level values.
- `each` against the same loop written by hand: identical results.
- Python and Rust produce byte-identical output on the corpus and on generated
  programs.
- One wrong program per checker rule, each of which must be rejected.
